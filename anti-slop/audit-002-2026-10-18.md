## Findings

### 9. HIGH (Hard Gate, R-03) Header email icon link is a 20x20 tap target

`src/components/Header.astro:45-49` renders the mail icon as a bare `<a>` with a `width="20" height="20"` SVG and no padding. Its tappable area is 20x20, below the 44px minimum R-03 requires, and below `DESIGN.md`'s own "never ship a control under a 44px touch target" clause. It sits 16px from the cart button, so the two targets overlap at the 24px spacing threshold as well.

The cart button already solves this the lazy way, `CartButton.astro:8` uses `before:absolute before:-inset-3 before:content-['']` to grow a 22px icon to a 46px hit area. Fix is one class on the mail link.

### 10. HIGH (Hard Gate, R-02) Em dashes in the shipped copy

22 occurrences across 18 source lines. They are not comments, they are user-visible or crawler-visible text:

- Page titles / meta descriptions: `404.astro:5`, `cart.astro:9`, `checkout.astro:12`, `contact.astro:7`, `contact.astro:8`, `incident-report.astro:9`, `order-thank-you.astro:5`, `config/site.ts:3`, `config/site.ts:5`
- Alt text: `index.astro:14`, `21`, `28`, `46`
- Body copy: `index.astro:70` ("Late nights, early dreams — the street is the studio"), `index.astro:79` (coordinates row), `catalog.ts:47` (MEDUSA blurb)
- Live UI strings: `checkout.astro:342` (courier / zone / days string built at runtime), `checkout.astro:230` (em dash used as the empty shipping-fee placeholder)

`DESIGN.md` (34), `PRODUCT.md` (9) and `README.md` (10) also use them heavily, which is why this is a question and not an automatic fix: under R-02's scope clause, the owner's own writing sample goes through the R-37 conflict protocol (name the character, name the rule, ask). If the em dash is Kalye Noir's voice it can stay, recorded as an owner override; if not, the fix is mechanical and confined to punctuation.

### 11. MEDIUM (R-19 / R-31 / Block 3) The dials are never declared

No `ENERGY / RHYTHM / MOTION` line exists anywhere, in `DESIGN.md` or elsewhere, and no Design Read is on record for the build. Block 3 requires the dials to be explicit and the output to match them, which is currently unverifiable. The site reads as ENERGY 2 / RHYTHM 2 / MOTION 2 (poster-led, one registration accent, scroll reveals plus hover on artwork), so the fix is one line in `DESIGN.md` recording what the build already does, not a redesign.

### 12. MEDIUM (R-31, direction drift) DESIGN.md declares a Reviews tab and wall that do not exist

`DESIGN.md` describes a fixed vertical reviews tab with a slide-over panel, a 2-up / 4-up photo wall and a first-class empty state as a signature component. `grep -i "review|star|rating|testimonial"` over `src/` returns zero component hits. Either build it or trim it from the direction file; a declared identity motif that is absent weakens the Block 3 identity lever and makes the doc lie about the build.

### 13. LOW (R-05) "How Ordering Works" is the exact 3-step template shape

`index.astro:162-202` is a three-column block of numbered steps (`01`, `02`, `03`) under a heading that maps to the rule's named pattern. The copy is genuinely product-specific (request slip, batch queue, Manila dispatch) and there are no round icons, but the skeleton is the AI default. Keep with a written reason, or reshape it into the print-slip / registration-mark motif the rest of the page uses.

### 14. LOW (R-15) Generic "Explore" CTAs on two pages

`cart.astro:145` "Explore Drop 001" and `404.astro:14` "Explore The Collection". "Explore" is on R-15's forbidden list. The storefront already has a better vocabulary in use ("See the drop", "View Tee", "Select a print"), so the fix is a wording swap, not new code.

### 15. LOW (R-08 / R-31) Four decorative arrows with no written reason

`index.astro:151` (View Tee), `index.astro:209` (Shop Now), `checkout.astro:399` (Select a print), `contact.astro:76` (File Incident Report). Not "almost every button", so the rule's dose cap is respected, but R-31 asks for the one-line reason. Either write it into `DESIGN.md` or drop them.

### 16. LOW (R-24 / R-38) "Track an Order" points at `/contact`

`config/site.ts:30`. The destination resolves (crawl: 0 broken links), but the label promises a tracking feature that does not exist anywhere in the app. Relabel to what `/contact` actually offers ("Order support") or build the tracking view.

# Follow-up: all eight findings fixed (2026-10-18)

### 9 (R-03) fixed
`Header.astro:48` now carries `relative before:absolute before:-inset-3 before:content-['']`, the same hit-area trick `CartButton.astro:8` already used. The mail icon measures 46px of tappable area instead of 20px, and the class is present in the built HTML on all 11 pages.

### 10 (R-02) fixed
23 em dashes removed from 19 source lines, the count being one higher than the audit's 22 because `products/[slug].astro:37` was hidden behind a PowerShell encoding bug and only showed up when the sweep was repeated with ripgrep. Replacements: page and product titles take a colon (`Cart: KALYE NOIR Street Wear Manila`), descriptions and blurbs take a colon or a period, alt text takes a colon, the hero line ends its sentence, the coordinate row takes a comma, and `checkout.astro:342` builds the courier window with the same `·` separator the rest of the site uses. `checkout.astro:230` uses a plain hyphen for the not-yet-calculated delivery fee. Verified: `grep` over `src/` and a node scan of `dist/` both return 0.

Still holding em dashes: `DESIGN.md` (34), `PRODUCT.md` (9), `README.md` (10). Those are owner documents rather than UI copy, so they were left alone.

### 11 (R-19 / R-31 / Block 3) fixed
